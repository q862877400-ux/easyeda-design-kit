## R1 走线/过孔资源与布线器能力（7 条）

**共同现象**：Connection Error 降不下去，集中在电源/地网与少数长跳；根因不是"没试够参数"，
而是**没有可用的走线级编辑**，也**没有过孔资源优化手段**。

- `GAP-008` 电源/地未连多数卡在缝合过孔位不足
- `GAP-017` `route-short` 对长跳与电源网无效，Connection 不降
- `GAP-019` U0TXD（U1.37 ↔ U3.3）多种参数下均不可解
- `GAP-021` 3V3 的 U3_4 焊盘被 DTR 走线封死，无法打散热孔
- `GAP-022` 5V_IN 的 D2_5 与 GND 的 J2_11 打不了有效孔
- `GAP-024` 焊盘内打过孔仍不连通（铺铜避让隔离）
- `GAP-025` 剩余未连只剩两个"孤岛"，都卡在没有过孔空间

**闭合条件**：布线器能对密集板跑出可解结果，**或**允许把单条走线挪开 1 mil（无此命令，见 GAP-053）。

## R2 DRC 几何闭环缺失（5 条）

**共同现象**：板子能连通，但 DRC 总有 1–27 条**微米级**违规；试着修，发现三条路都被堵死：
无走线级编辑（GAP-053）、无 PCB 备份（GAP-053）、布线器间距模型与 DRC 口径不一致（GAP-058）。

- `GAP-030` PCB Auto Router 335/335 连通，但留 3 条微米级间距误差
- `GAP-050` 旧口径只认 Connection Error → "全绿"不等于 DRC 0
- `GAP-052` 两条间距差 0.1/0.9 mil；Netlist Error 同步+重载后仍在
- `GAP-053` 缺走线级编辑 + PCB 备份导出失败
- `GAP-058` 两次独立重建得到**逐条相同**的 3 条违规 ⇒ 不可达（工具链限制）

**闭合条件**：任一即可——布线器支持 slot/pad 级 clearance；或给 CLI 加走线级编辑；或 PCB 备份可用后手工改线。
**2026-11-01 补充**：`pcb.components.list` 支持 `includePads`，**可能**提供焊盘级数据（R2/R5 共同缺的那条），
但**未验证**（本轮无窗口，未取到真实 pads 内容）。这是当前最值得先验的一件事。

## R3 组包络与 A4 排版（6 条）

**共同现象**：器件组（本体+netport marker+桩线）互相压、或被推到图框外；`destagger` 自称搬了但几何不变；
A4 尺寸又没有 API 可改。**根因是"组包络"这个量既不可控也不可预测**——而它恰恰是 `clusters --strict` 的判据。

- `GAP-034` 默认模板布局过不了 clusters，destagger 是"假进展"
- `GAP-041`/`GAP-042`/`GAP-044` 六件块与 A4 的尺寸冲突（919×672 vs 可用 1170×627）
- `GAP-046` 放不下的预测**非单调**（220/260 接受，240/250 拒绝）
- `GAP-047` 进框/网表对齐/无重叠三方权衡

**闭合条件**：让 destagger 真收敛，或布局阶段就把 marker 包络当约束（当前只能靠"试参数 + 挪单件 + 错开桩长"的经验配方，见 `playbooks/big-block-fit`）。

## R4 GUI 自动化前置与环境回收（5 条）

**共同现象**：凡是必须点界面的动作（导入、打开文档、手工导出），都会撞上"浏览器没连 / 会话 5 分钟回收 /
原生文件框 / 扩展懒渲染"。

- `GAP-027`/`GAP-028` 扩展广场可装但清单不可信（懒渲染）
- `GAP-032` 网页版导入需要原生文件框；无 file-input 能力（**已通过 UI 走通，见 GAP-032 结案**）
- `GAP-057` 重建流程被窗口掉线打断
- `GAP-061` 导入板连接器绑不上（需 UI 点工程名）

**闭合条件**：稳定的浏览器+扩展连接与会话保活（见 GAP-064 三前置）；**其中"打开浏览器"是人类动作**。

## R5 外部板特有的 DSN/绑定（2 条）

- `GAP-059` / `GAP-063`：`ESP32S3_USB` 的 `pcb export-dsn` 持续报"没有网络"，即使文档已激活
  （`documentType=pcb`、`documentUuid` 正确）。首要嫌疑是 DFM 报的那个畸形焊盘。

**闭合条件**：焊盘级诊断能力（CLI 无），或在 GUI 里手工导出 DSN 做二分。

## R6 CLI 只读查询缺口（2 条）—— **已闭合**

- `GAP-006` 没有 `silk-list` 这类查询命令
- `GAP-035` `sch group-move --ids` 只认 primitiveId，传位号 `ok:false`

**闭合条件**：**已闭合（GAP-065）**。`easyeda actions` 的 169 条动作里本来就有 `pcb.silk.list`（只读、含 layer/mirror/componentId）、
`pcb.components.list`（含 `includePads`）与 `schematic.designators.list`（designator→parentId）。
本轮验证了 `easyeda call <action> --payload` 通道有效（未知动作返回 `UNKNOWN_ACTION`，真实动作在无窗口时报 `--doc guard`）。
**教训**：「CLI 没这个子命令」≠「能力不存在」——以后先查动作目录再下结论。

## R7 扩展「装上 ≠ 能用」（1 条）

- `GAP-029` PCB Auto Router 主程序已装、免费额度够，但需**登录**，且原生 GUI 无法自动化。

**闭合条件**：扩展的授权自动化（当前不可能：原生桌面程序不可驱动）。

## 这张图怎么用

1. **报告进度时按根因报，不按条数报**：说"还有 7 个根因"，而不是"还有 28 个问题"。
2. **排优先级看闭合条件是否可得**：R4 只差业主开浏览器；R1/R2/R3/R5 都卡在同一条"缺走线级编辑/焊盘级诊断"，
   说明**真正值得投资的是那一件工具能力**，而不是逐个现象打补丁。
3. **新增条目时先归因再记**：如果它落在某个已有根因里，就在该根因下追加，不再新开一节——
   避免边界文件继续膨胀成 100 条。
