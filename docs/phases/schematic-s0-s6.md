# 原理图阶段 S0–S6

**用途**：把"画原理图"拆成 7 个有进入/退出判据的阶段。每个阶段的 `退出判据` **必须是命令或数字**，
不接受"看起来合理"。

**通用纪律**

- `动作` 一栏只写**具名工具**（扩展 / 命令 / 动作）；不写"写个脚本"。
- 任一阶段失败 → `失败处置` 三选一：修 / 换工具 / 报 BLOCKED，**不得静默跳过**。
- 需要参考的能力边界见 `docs/capability-boundary.md`；工具细节见 `docs/tool-decision-table.md`。

---

## S0 需求解析与器件选型

| 项 | 内容 |
|---|---|
| **进入条件** | 拿到客户需求文本（如 `esp32MiniRequire.md`） |
| **动作** | `主控芯片AI助手`（查立创商城型号/封装）→ `数据手册AI助手`（取数据手册）→ `knowledge.query`（查规则依据） |
| **退出判据** | ① 每个器件有明确型号与封装；② 每个电源轨标注电压/电流；③ 需求里的每条硬约束（层数、板框、接口）都有对应器件或结构件 |
| **失败处置** | 器件查不到 → **停下向业主索取**，禁止猜封装 |

**坑**：不要凭记忆写引脚——用 `数据手册AI助手` 取真实引脚。

---

## S1 建库（符号 / 封装 / 器件）

| 项 | 内容 |
|---|---|
| **进入条件** | S0 PASS，器件清单确定 |
| **动作** | `符号提取助手`（图片→符号）/ `AI智能建库`（生成符号+封装）/ 立创库直接引用 |
| **退出判据** | ① 每个器件可放置且引脚数与数据手册一致；② 封装焊盘尺寸与 datasheet 推荐值一致；③ 库中无重复符号 |
| **失败处置** | 引脚数不符 → 回 S0 核对型号；禁止"先放上去再说" |

---

## S2 分页与模块划分

| 项 | 内容 |
|---|---|
| **进入条件** | S1 PASS |
| **动作** | `AI巧绘`（生成初版）/ `PCB器件分组器`（按图页分组，供后续 PCB 复用）/ 人工调整图页 |
| **退出判据** | ① 每页有清晰功能边界（主控/电源/USB/按键/LED）；② 跨页连接全部用网络标签，无悬空短线；③ 每个器件实例只出现一次 |
| **失败处置** | 同器件重复实例 → 合并；跨页直连 → 改网络标签 |

---

## S3 连接与网络命名

| 项 | 内容 |
|---|---|
| **进入条件** | S2 PASS |
| **动作** | `AI巧绘` 生成连接 / `批量放置元件`（导入 CSV）/ `网表重建原理图`（从网表恢复） |
| **退出判据** | ① `信号缺失检测助手` 报告 0 条悬空/孤立；② 网络命名遵循约定（`USB_DP`/`U0TXD`/`GND`/`3V3`…）；③ 关键网络有标签、可被 PCB 侧检索 |
| **失败处置** | 悬空 → 补连接或删；命名混乱 → 统一后重跑检测 |

---

## S4 电源与去耦

| 项 | 内容 |
|---|---|
| **进入条件** | S3 PASS |
| **动作** | `原理图自动去耦喵`（主电容+去耦电容+标签成套放置）/ `电源网络高亮助手`（用通配符 `*gnd*`/`vcc*`/`+*` 逐轨核对） |
| **退出判据** | ① 每个电源脚附近有去耦电容（数量按数据手册）；② 每条电源轨在原理图上连续可追；③ 磁珠/电感贯通后仍能高亮出完整通路 |
| **失败处置** | 缺去耦 → 补；轨断裂 → 查 S3 命名 |

---

## S5 原理图 DRC 与自检

| 项 | 内容 |
|---|---|
| **进入条件** | S4 PASS |
| **动作** | `schematic.runDrc` → `schematic.runDrcDetailed`（带明细）/ `BOM元件查重` |
| **退出判据** | ① `sch drc` 返回 `passed: true`；② BOM 无重复位号/等效值冲突；③ 每个网络至少 2 个端点 |
| **失败处置** | DRC 报错 → 按明细逐条修；**禁止**为了过 DRC 改需求 |

---

## S6 输出与转 PCB 准备

| 项 | 内容 |
|---|---|
| **进入条件** | S5 PASS |
| **动作** | `局部原理图网表导出`（Netlist_SCH_V3.0）/ `板卡拓扑导出器`（只读拓扑 JSON）/ 转 PCB |
| **退出判据** | ① 导出的网表可被 PCB 侧导入且无未匹配器件；② 拓扑 JSON 里网络数与原理图一致；③ 每个器件有对应 PCB 封装 |
| **失败处置** | 未匹配 → 回 S1 补封装；网络数不符 → 回 S3 |

**这一步之后进入 PCB 阶段 P0**（见 `pcb-p0-p10.md`）。

---

## 阶段依赖与门禁映射

```text
S0 → S1 → S2 → S3 → S4 → S5 → S6 → P0
```

| 阶段 | 对应验收要素 |
|---|---|
| S5 | `acceptance/run.ps1` 的 `schematic-gates` 阶段（`sch drc passed`） |
| S6 | 转 PCB 前的最后一道；PCB 侧 P2 的 `import-changes` 依赖它的输出 |

**已知边界**：`GAP-006`（无 silk-list 类命令）不影响原理图阶段；
`GAP-001/002` 属于 PCB 布线，不在此列。
